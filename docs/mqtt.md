## Быстрый старт с Home Assistant

1. Убедитесь, что работает аддон **Mosquitto broker** (или любой другой MQTT-брокер) и в HA настроена **интеграция MQTT**.
2. На дашборде шлюза откройте вкладку **MQTT** и заполните:
   - **Хост / порт** — адрес брокера (для аддона HA: IP хоста Home Assistant, порт `1883`)
   - **Логин / пароль** — учётка брокера (заведите для устройства отдельного пользователя)
   - **Префикс** — базовый топик, по умолчанию `esp-ot-gateway`
   - **Интервалы статуса / статистики** — как часто устройство публикует данные (см. ниже)
3. Сохраните. Через несколько секунд индикатор подключения станет зелёным, публикуется discovery, и в HA → Настройки → Устройства и службы → MQTT появляется новое устройство с **29 сущностями**.

YAML не нужен. Если сущности не появились — опубликуйте любое сообщение в командный топик повторного discovery (ниже) или нажмите *Re-announce* на вкладке MQTT.

## Поведение подключения

- **MQTT 3.1.1**, QoS 0, keepalive 60 с, стабильный client ID на основе MAC-адреса чипа.
- **Доступность (LWT):** устройство регистрирует retained-завещание `offline` и публикует retained-сообщение `online` при каждом подключении — HA помечает сущности недоступными в тот же момент, когда брокер теряет устройство.
- **Надёжность:** клиент без динамических аллокаций, keepalive через PINGREQ, watchdog «тихого» разрыва, автопереподключение с нарастающим графиком — **5 → 10 → 20 → 40 → 60 с, а после 5 неудач подряд — попытка раз в 5 минут**. Discovery-конфиги для HA публикуются заново после каждого реконнекта.
- **TLS:** опционально, по умолчанию выключен (переключатель на вкладке MQTT). Весь клиент можно отключить главным выключателем MQTT на той же вкладке.
- **Интервалы** настраиваются на вкладке MQTT и сохраняются в NVS:
  - статус: по умолчанию **30 с**, диапазон 5–3600 с
  - статистика: диапазон 30–86400 с

### Payload управления

Отправьте JSON-объект с любым подмножеством полей:

| Поле | Тип | Диапазон | Значение |
|---|---|---|---|
| `ch_enable` | bool | — | отопление вкл/выкл |
| `ch_setpoint` | число | 20–80 °C | уставка температуры подачи |
| `dhw_enable` | bool | — | горячая вода вкл/выкл |
| `dhw_setpoint` | число | 35–80 °C | уставка ГВС |

Значения вне диапазона обрезаются (дополнительно ограничиваются границами, сообщёнными котлом, — на вкладке «Инфо»; например, CH 25–80 °C, ГВС 35–60 °C на проверенном Baxi); некорректный JSON игнорируется и пишется в журнал событий.

Пример — установить отопление на 55 °C и убедиться, что оно включено:

```bash
mosquitto_pub -h <broker> -u <user> -P <pass> \
  -t 'esp-ot-gateway/control' \
  -m '{"ch_enable": true, "ch_setpoint": 55}'
```

Послушать всё, что говорит устройство:

```bash
mosquitto_sub -h <broker> -u <user> -P <pass> -v -t 'esp-ot-gateway/#'
```

### Payload событий журнала

Топик `<prefix>/journal` (QoS 0, retain=0):

```json
{"event_type": "system", "message": "MQTT: подключён к 192.168.1.100", "ts": 1783958400, "ts_valid": true}
```

| Поле | Тип | Значение |
|---|---|---|
| `event_type` | строка | категория: `system`, `user`, `equip`, `mode`, `boot` |
| `message` | строка | точный текст записи из журнала |
| `ts` | число | Unix-таймстемп события |
| `ts_valid` | bool | `true` если SNTP синхронизирован (время достоверно) |

**Осознанные потери:** события до подключения к брокеру и во время разрывов в HA не попадают. Журнал на устройстве (вкладка «Журнал») — полный источник истины, MQTT — только live-лента.

## Примеры автоматизаций

Ночное снижение температуры:

```yaml
alias: Ночное снижение
trigger:
  - platform: time
    at: "23:00:00"
action:
  - service: number.set_value
    target:
      entity_id: number.esp_ot_gateway_ch_setpoint
    data:
      value: 45
```

Уведомление об аварии котла:

```yaml
alias: Авария котла
trigger:
  - platform: state
    entity_id: binary_sensor.esp_ot_gateway_fault
    to: "on"
action:
  - service: notify.mobile_app_phone
    data:
      message: "Котёл сообщает об аварии — посмотрите код ASF/OEM на вкладке Инфо."
```

*(entity_id зависят от вашего нейминга в HA — скопируйте реальные со страницы устройства.)*

Уведомление о событии журнала (например, ошибка котла):

```yaml
alias: Ошибка в журнале
trigger:
  - platform: state
    entity_id: event.zal_kontroller_kotla_zhurnal_kotla
action:
  - service: notify.mobile_app_phone
    data:
      message: "{{ trigger.to_state.attributes.message }}"
```

## Мониторинг самого MQTT-канала

- Вкладка **MQTT** дашборда показывает живое состояние подключения, последнюю ошибку и счётчики реконнектов.
- REST: `GET /api/mqtt/status` возвращает то же самое в JSON (см. [api.md](api.md)).
- Со стороны брокера: лог аддона Mosquitto показывает подключения/отключения по client ID.
