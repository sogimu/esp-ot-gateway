## Context

`PidPollInteractor` держит отдельный гистерезис по комнате (цель ± `pid_hysteresis`), а выход PI ограничен физическим максимумом котла (`ch_sp_max`, обычно 80 °C). Для тёплого пола это даёт уставку до 63 °C и не даёт ей снижаться. Нужен чистый PI: выход — уставка подачи в заданных пользователем границах, а вкл/выкл CH выводится из выхода.

## Goals / Non-Goals

**Goals:**
- Настраиваемые `pid_sp_min`/`pid_sp_max`, персист в NVS, поля в API и вебе.
- Чистый PI без комнатного гистерезиса; интеграл свободно уменьшается.
- Вкл/выкл CH по выходу PI с маленьким deadband.

**Non-Goals:**
- Не меняем цикловую блокировку и защиту от перегрева (работают как override).
- Не вводим feed-forward/погодную кривую.

## Decisions

- Выход PI = `clamp(P+I+D, lo, hi)`, где `lo/hi` — `pid_sp_min/pid_sp_max`, зажатые по ID 49.
- Интеграл инициализируется в `lo` при включении PID — выход сразу на минимуме, без мёртвой зоны.
- `ch_on`: латч по выходу — вкл при `out ≥ lo + deadband`, выкл при `out ≤ lo`.
- `pid_hysteresis` переиспользуется как deadband по выходу (семантика меняется).
- При `ch_on=false` уставка = `lo`, бит CH гасится гейтом в `build_master_byte` по `pid_ch_enabled`.

## Risks / Trade-offs

- [Смена семантики `pid_hysteresis`] → значение 0.1–0.5 °C остаётся разумным; обновляем подпись в вебе.
- [Потолок по умолчанию 40 °C может не подойти другим домам] → настраивается через API/веб.
