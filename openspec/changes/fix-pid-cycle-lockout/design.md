## Context

`PidPollInteractor::execute()` сейчас содержит две ветки, которые принудительно снижают уставку CH до `sp_lo_`:

- ветка перегрева (`pid_poll_interactor.cpp:147-158`) — при комнате выше 30 °C;
- ветка блокировки цикла (`:162-172`) — при `cycle_locked_ == true`.

В обеих ветках также обнуляются P/I/D и подменяется `pid_output` на `sp_lo_`. Фактическая уставка формируется `BoilerPollInteractor::do_extra_step()` из `state_.get_ch_setpoint()`, поэтому в котёл уходит 25 °C.

При этом остановка котла уже обеспечена битом CH: в PID-режиме `BoilerPollInteractor::build_master_byte()` гасит `MASTER_CH_ENABLE`, когда `pid_ch_enabled == false` (`boiler_poll_interactor.cpp:353-356`). Бит CH — штатный запрос тепла OpenTherm и надёжно управляет котлом; уставка для вкл/выкл не нужна.

## Goals / Non-Goals

**Goals:**
- Убрать скачки уставки до `sp_lo_` при выключении CH, блокировке цикла и перегреве.
- Оставить единственным органом вкл/выкл бит CH enable.
- Сохранить уставку результатом PI: она может плавно меняться, но не подменяется константой.
- Сохранить блокировку цикла как запрет повторного включения на `pid_lockout_sec`.
- Сохранить защиту от перегрева как запрет нагрева; уставка при этом не паркуется.

**Non-Goals:**
- Не менять алгоритм PI, границы `pid_sp_min`/`pid_sp_max`, гистерезис и таймер блокировки.
- Не менять логику DHW, ручных режимов и расписания.
- Не вводить отдельный флаг «ручное выключение»: `ch_enable` и `pid_ch_enabled` уже выполняют свои роли.

## Decisions

1. **Блокировка цикла — только бит.** Ветка `cycle_locked_` перестаёт быть отдельным ранним выходом: после расчёта PI и гистерезиса выполняется `if (cycle_locked_) ch_on = false;`. `set_pid_state(...)` получает актуальные `output`, P/I/D, `cycle_locked_`, `remaining` и `ch_on = false`.
2. **Уставка всегда пишется из `output`.** В обычной ветке `state_.set_ch_setpoint(output)` вызывается и при `ch_on == false` — уставка остаётся результатом PI. `sp_lo_` используется только как нижняя граница в `compute_pid()`.
3. **Перегрев — только бит.** При комнате выше `MAX_SAFE_ROOM` бит CH гасится немедленно (до проверки `dt`), но `output`/P/I/D и уставка не подменяются. На тиках расчёта PI продолжает обновлять уставку.
4. **Логи без «SP 25».** При блокировке писать остаток времени и текущую уставку PI, а не `sp_lo_`. Обычная строка `PID: SP=...` продолжает печатать `output`.
5. **Тесты доказывают отсутствие подмены.** Для блокировки и перегрева использовать `Kp = Ki = 0` и базу 30 °C, чтобы выход PI гарантированно отличался от `sp_lo_` (25 °C) и тест падал при возврате старого поведения.

## Risks / Trade-offs

- **[Котёл игнорирует CH enable]** → защиты низкой уставкой не будет. Принято: на проверенном Baxi бит CH работает, а текущая gating-логика уже полагается на него; исходный баг был в том, что бит вообще не гасили.
- **[PI при блокировке естественно доходит до `sp_lo_`]** → это нормальное поведение регулятора (нижняя граница `pid_sp_min`), а не принудительная парковка; скачка из-за выключения нет.
- **[Перегрев без снижения уставки]** → остановка только битом. Если понадобится аварийный fallback, его можно вернуть отдельной настройкой, не смешивая с обычным выключением.
- **[Уставка при `ch_on == false` продолжает меняться]** → это ожидаемое поведение по требованию; на момент повторного включения уставка уже готова, без ступеньки к минимуму.
