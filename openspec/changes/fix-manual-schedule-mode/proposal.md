## Why

Подрежим «Ручной по расписанию» (`CHMode::Manual_Sched`, mode 2) не работает: суточная сетка уставок CH нигде не применяется к котлу — `ScheduleService::evaluate()` является мёртвым кодом, который никто не вызывает. Пользователь выбирает режим, редактирует и сохраняет расписание, но уставка CH остаётся замороженной на последнем статичном значении. Дополнительно ручное расписание не переживает перезагрузку, а интерфейс его редактирования визуально не согласован с панелью ручного статичного режима.

## What Changes

- Применить почасовую уставку CH из расписания в контуре управления (аналог уже работающего `PID_Sched`), когда активен режим `Manual_Sched` и расписание включено.
- Подключить существующий `ScheduleService` (или эквивалентную логику) к расчёту уставки по локальному часу.
- Персистить `CH_Schedule` (включая флаг `enabled`) в NVS наравне с уже сохраняемым `PID_Schedule`.
- Добавить поле `hour` (локальный час) в ответ `GET /api/schedule` — по аналогии с `GET /api/pid_schedule`, чтобы статусная строка в вебе показывала текущий час и уставку вместо вечного «NTP...».
- Привести интерфейс редактирования расписания к дизайну ручного статичного режима: единые подписи (например, «Уставка CH» вместо «Температура»), единое расположение виджетов (ползунок между кнопками −/+, значение температуры справа), единый стиль подсказок.
