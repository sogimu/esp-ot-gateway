## Context

`GasFlowService::execute()` уже раз в тик читает флаг `dhw_active` из состояния (`gas_flow_estimator.cpp:90,93`), но использует его только в `calc_power()` для выбора `dhw_pmin/pmax` против `ch_pmin/pmax` (`:70-71`). Сами накопители расхода — `daily_accumulator_`, `hourly_accumulator_`, `today_hours_[24]`, `daily_[].m3` — хранят только суммарный объём, без признака режима.

График (`drawGasBars`, `web_page.h:1461`) рисует один `<rect>` на столбик; данные приходят из `render_gas_history()` (`web_presenter_adapter.cpp:345`) с полем `m3`.

Нужно: раскладка расхода на ГВС (БКН) и Отопление в каждом столбике (час/сутки) с цветовой нотацией и легендой. Единицы — только м³, абсолютные значения.

## Goals / Non-Goals

**Goals:**
- Параллельно суммарному расходу накапливать долю, приходящуюся на режим ГВС (`dhw_active == true`).
- Хранить раскладку в NVS (`m3_total` + `m3_dhw`) с той же стратегией «частый today + редкий history».
- Отдавать раскладку в `/api/gas-history`.
- Рисовать двухцветный столбик (Отопление зелёный, ГВС оранжевый), легенду, туллип и «Итого» с тремя значениями.
- Маркировать «сегодня» только непрозрачностью (1.0 против 0.7).

**Non-Goals:**
- Дробление на более тонкие категории (например, только нагрев проточной ГВС vs БКН) — не делаем.
- Пересчёт в деньги/энергию.
- Миграция старой истории (затираем — см. D3).
- Раздельная выдача раскладки в MQTT (`/stats` не трогаем).

## Decisions

### D1. Представление: `m3_total` + `m3_dhw` (абсолютные)

Каждый bucket хранит суммарный объём (`m3_total`) и объём ГВС (`m3_dhw`). Доля отопления не хранится, считается на фронте как `m3_total − m3_dhw`.

Альтернативы:
- **Два абсолютных (`m3_dhw` + `m3_ch`)**: симметрично, но дублирует total и удваивает все поля/сценарии.
- **Доля `dhw_frac` (0..1)**: компактно, но «плавает» при округлениях и усложняет пересчёт при обнулении.

Выбрано `m3_total + m3_dhw`: минимальная дельта, total остаётся источником правды, `ch` выводится разностью. Отрицательная разность при плавающем округлении исключается на фронте clamp'ом `≥ 0`.

### D2. Атрибуция по тику через `dhw_active_`

В `execute()` флаг `dhw_active_` уже снят в начале тика (`:93`). При интеграции (`:147-153`) добавляем:

```
dv = flow * dt_h
daily_accumulator_   += dv   // total
hourly_accumulator_  += dv   // total
if (dhw_active_) {
    daily_accumulator_dhw_  += dv
    hourly_accumulator_dhw_ += dv
}
```

Смена режима между тиками приписывает тик целиком к режиму на момент его начала — погрешность ≤ одного тика, приемлемо (та же аппроксимация, что и у flame-gating).

### D3. NVS: без миграции

`GasTodayBlob` и `GasHistoryBlob` расширяются DHW-полями, их `sizeof` меняется. Существующие `load_today_gas`/`load_history_gas` уже проверяют `sz == sizeof(...)` (`gas_correction_nvs_store.cpp:115,139`) и вернут «нет данных» для старого формата — история начнётся с нуля без спецкода. Никакого версионирования/миграции не вводим (решение заказчика: «готов потерять»).

Размеры: `GasTodayBlob` ~116 → ~220 Б; `GasHistoryBlob` ~876 → ~1230 Б. Партиция NVS 24 КБ, лимит blob ~4 КБ — запас достаточный.

### D4. Фронт: stacked-бар + легенда

В `drawGasBars` вместо одного `<rect>` рисуется два:
- нижний — Отопление, `#a5d6a7` (зелёный), высота `h_total − h_dhw`;
- верхний — ГВС, `#ff7043` (оранжевый), высота `h_dhw`.

Геометрия столбика (ширина, отступы, скругление) не меняется. Маркер «сегодня» — только непрозрачность: текущий bucket `opacity=1.0`, прошедшие `0.7` (красный `#e94560` убирается).

Легенда — компактная строка возле заголовка: `█ Отопление · █ ГВС`.

### D5. Туллип и «Итого» — три значения

- Туллип: `<метка>` (+ пометка «сейчас» для сегодняшнего bucket) + `ГВС: X м³` / `Отопление: Y м³` / `Всего: Z м³` (абсолютные, 3 знака).
- «Итого» (`gas_total`): `ГВС: X м³ · Отопление: Y м³ · Всего: Z м³`.

Фронт хранит в `gasChartData` помимо `values` (total) массив `dhwValues`; `ch = total − dhw` считается на месте.

## Risks / Trade-offs

- **Потеря старой истории при OTA** → намеренно; `sz != sizeof` даёт чистый старт без краша.
- **Атрибуция на границе переключения режима** → ошибка ≤ одного тика; некритично для часовых/суточных bucket'ов.
- **Плавающая разность `total − dhw`** → clamp `≥ 0` на фронте; в норме `dhw ≤ total` по построению.
- **Размер `/api/gas-history`** → +1 float на запись (~+450 Б на ~112 записей); буфер 8 КБ покрывает.
- **Цветовая коллизия** → циан `#4fc3f7` больше не используется для «общего» бара; в диаграмме клапана циан = ГВС, но в газовом графике ГВС = оранжевый. Принято осознанно (разные панели).
- **Изменение `m3` → `m3_total` ломает тесты и JSON** → обновляются `test_gas_daily_tracking.cpp`, `test_gas_integration.cpp`, `test_gas_flow_bugs.cpp` вместе с кодом.

## Migration Plan

1. Структуры и ключи NVS расширяются на месте; старый формат не читается (см. D3).
2. Откат на старую прошивку: старые blob'ы не были перезаписаны корректным новым форматом? — они перезаписываются новыми ключами `today`/`history`, поэтому даунгрейд после апгрейда просто затрёт раскладку (старая прошивка не знает новых полей и читает только при совпадении размера — не совпадёт, история начнётся заново). Полный даунгрейд безопасен, история при этом не сохраняется.
3. Развёртывание через OTA: новое поведение включается сразу, без флагов.
