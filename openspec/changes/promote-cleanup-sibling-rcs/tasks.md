## 1. Пайплайн: уборка всех rc промоутируемой версии

- [ ] 1.1 В `tests.yml` (шаг «Publish GitHub Release», ветка создания нового стабильного релиза) заменить удаление одного `SOURCE_RC` на перебор `git ls-remote --tags origin "refs/tags/${TAG}-rc*"` с фильтром `^${TAG}-rc[0-9]+$`; для каждого тега — `gh release delete --yes` (best-effort) и `git push origin ":refs/tags/<rc>"` (best-effort).
- [ ] 1.2 Сохранить guard: `CHANNEL=stable && -n SOURCE_RC`, и выполнение только при создании нового релиза (не при уже существующем стабильном релизе).
- [ ] 1.3 Убедиться, что теги других версий не попадают под фильтр (`^${TAG}-rc[0-9]+$`).

## 2. Проверка

- [ ] 2.1 Локальный сухой прогон фильтра на наборе тегов (`v0.8.1-rc1`, `v0.8.1-rc2`, `v0.9.0-rc1` → выбираются только `v0.8.1-*`).
- [ ] 2.2 E2E на релизной ветке: два rc одной версии → мерж PR → оба rc-релиза/тега удалены, стабильный создан, тестовый тег другой версии не тронут.
- [ ] 2.3 Повторный прогон / запуск при уже существующем стабильном релизе уборку не выполняет.
