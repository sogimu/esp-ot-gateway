## Why

Три слабых места текущего PI:
1. Цикловая блокировка взводится по пламени, поэтому штатное тактование котла на малой нагрузке гасит отопление на 120–300 с.
2. Интеграл считается по фиксированному `dt`, а не по фактическому интервалу — задержки опроса искажают накопление.
3. Старт после смены режима всегда с минимума (долгий выход), а при перегреве интеграл рассасывается слишком медленно (перелёт).

## What Changes

- **Блокировка по CH, не по пламени**: таймер взводится переходом `pid_ch_enabled` true→false (решение самого PI). Погасание пламени котла игнорируется. `pid_cycle_lockout = 0` отключает блокировку.
- **Фактический `dt`**: интеграл использует реальный интервал с прошлого расчёта (clamp 1–300 с) вместо значения из конфига.
- **Bumpless-старт**: при включении PID/смене режима интеграл стартует с последней рабочей уставки (RAM), а не с минимума; после ребута — с минимума.
- **Быстрое рассасывание**: при комнате выше цели интегральный коэффициент временно ×3 (асимметрия), чтобы уставка снижалась быстрее без роста числа циклов.
